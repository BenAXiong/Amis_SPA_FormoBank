# decisions.md

This file records durable implementation choices for the Amis-Mandarin MT Review Demo. Keep alternatives open where noted, but default to these choices unless a later entry supersedes them.

| Date | Decision | Rationale | Alternatives kept open | Related plan refs |
| --- | --- | --- | --- | --- |
| 2026-05-22 | Keep `packages/shared` in the repository structure. | `AGENTS.md` requires it, and shared constants/types reduce drift between frontend, API routes, and tests. | If it stays very small, it can remain minimal and contain only shared types/constants. | `PLAN.md` section 6 |
| 2026-05-22 | Use Next.js API routes for feedback writes to Supabase. | This keeps the Supabase service role key server-side and avoids broad anonymous table policies. | A narrow anonymous insert policy can be considered later if server routing becomes unnecessary. | `PLAN.md` sections 5, 7, 8, 13 |
| 2026-05-22 | Enable RLS on all Supabase tables and expose no public select policies for feedback/review tables in v0. | Public users should be able to submit consented feedback but not inspect stored feedback. | Authenticated reviewer read policies can be added in a later reviewer phase. | `PLAN.md` sections 7, 13, 15 |
| 2026-05-22 | Add `mt_annotation_reviews` schema now, but do not build a reviewer dashboard in v0. | The table is required for the future review workflow, while the UI for review/export belongs after the public translation and feedback loop works. | Phase 5 can add reviewer login, table view, CSV export, and review status workflows. | `PLAN.md` sections 7, 10, 17 |
| 2026-05-22 | Treat export/reviewer tooling as Phase 5, not a v0 public deployment blocker. | The first public app should prioritize translation, explicit-consent feedback storage, and deployment. | A simple server-side export script can be added earlier if review operations become urgent. | `PLAN.md` sections 10, 16, 18 |
| 2026-05-22 | Use Modal as the default inference path with conservative resource settings. | Modal gives direct Python/runtime control and matches the project default. Conservative defaults avoid requiring cost/performance choices before real usage data exists. | Hugging Face Inference Endpoint remains documented as the managed-hosting alternative. | `PLAN.md` sections 2, 9, 15 |
| 2026-05-22 | Do not implement user accounts in v0. | Anonymous public demo plus explicit consent is enough for the first translation and annotation loop. | Supabase Auth can be added for reviewer-only pages in Phase 5. | `PLAN.md` sections 3, 10, 17 |
| 2026-05-22 | Keep request limits conservative: 800 input characters and 160 max new tokens. | The app is for short sentences and small paragraphs, not long-document translation. | These values can become environment-configured deployment settings. | `PLAN.md` sections 4, 8, 12, 13 |
| 2026-05-22 | Use GitHub repository `BenAXiong/Amis_SPA_FormoBank`. | The app should live in its own source repository even if it shares a Supabase project with another app. | Repository remote can be added when Git is initialized locally. | `PLAN.md` sections 2, 16, 18 |
| 2026-05-22 | Isolate shared Supabase usage with `mt_` table names. | The app may use another repo's Supabase project due to project limits, so namespacing prevents table and migration collisions. SQL identifiers with hyphens require quoting, so use `mt_` instead of `mt-`. | A dedicated Supabase project or dedicated Postgres schema can replace prefixes later if available. | `PLAN.md` sections 7, 13, 15 |
| 2026-05-22 | Use local development port `3003`. | Keeping a stable project-specific port avoids collisions with other local apps. | Vercel deployment remains unaffected; the port is local only. | `PLAN.md` section 12 |
| 2026-05-23 | Keep `FormosanBank/nllb200-formosan-zh` as public attribution, but use public directional checkpoints at runtime. | The broad model page is the right user-facing attribution, while the deployable public files are available through `FormosanBank/nllb200-formosan-zh-spm8k` and `FormosanBank/nllb200-zh-formosan-spm8k`. | A private Hugging Face token or managed HF endpoint can be used later if the original repo is required directly. | `PLAN.md` sections 1, 8, 9 |
